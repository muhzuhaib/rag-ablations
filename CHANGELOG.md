# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/spec/v2.0.0.html). While the major version is `0`, the
public API may change between minor versions.

A published benchmark number is part of this project's public interface. **Any change that moves a
figure in the README will be called out here explicitly, with the old value and the new one**, even
when nothing in the API changed. A benchmark whose numbers drift quietly is worth nothing.

`v0.1.0` was tagged after the fact and marks the repository as it stood when 0.1.0 went to PyPI on
2026-07-31.

## [Unreleased]

### Added

- A recorded demo at the top of the README, generated by the committed `docs/record_demo.py` from a
  real run rather than assembled by hand, so it can be re-recorded when the output changes.
- `CONTRIBUTING.md`, `SECURITY.md`, issue templates and Dependabot.
- A monthly scheduled CI run of the reproducibility gate, so a benchmark that has stopped
  reproducing is noticed without waiting for someone to push.

## [0.1.0] - 2026-07-31

First release, [on PyPI](https://pypi.org/project/rag-ablations/). The ablation table and the
baseline it is measured against are both complete.

### Added

- **nDCG@10 and recall**, with tests worked by hand against values computed independently, because
  every other number in this project is only as good as the metric under it.
- **A BM25 baseline**, validated against the published BEIR figures rather than declared correct.
  Without that check, an improvement is measured against an unknown.
- **BEIR corpus loading** using the standard library only, so reproducing the benchmark needs no
  account and no download tooling.
- **Dense retrieval** with local `sentence-transformers` embeddings, so the whole benchmark runs on
  a laptop CPU with no API key and no spend.
- **Hybrid retrieval** by reciprocal rank fusion, and **cross-encoder reranking**.
- **Chunking strategies** with document-level pooling.
- **A retrieval API and a container**, both started and queried by CI rather than only built.
- **A reproducibility gate in CI**: the published SciFact baseline and the chunking ablation are
  re-run on every push and the build fails if a figure moves, which is what stops the README drifting
  away from the code.
- **The dense, hybrid and reranking results**, published with the negative ones kept in: dense
  retrieval loses to BM25 on this corpus, and the reranker is neutral at best while being far slower.

### Fixed

- `data/` and `results/` were located by walking up from `__file__`, which is correct inside a source
  checkout and silently wrong when the package is installed from a wheel. Found by installing the
  built wheel into a clean environment and using it the way a stranger would, not by a failing test.
